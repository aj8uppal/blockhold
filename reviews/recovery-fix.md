# Repair interrupted co-op battles after the rebalance

The previous release accepted ruleset-nine journals but replayed their Seraph attacks with ruleset-ten values. Once a tier-four/five Seraph attacked, the replay diverged and failed its final state check. The original journal was retained, but Continue returned to the menu.

Recovered ruleset-eight/nine battles now retain their original Seraph damage, intervals, target counts and Eclipse targeting. Their historical purchase orders use the original access checks; subsequent play uses current unlock access and has no Mythic quantity cap. The combat version and historical command boundary remain in later saves and co-op transfers. Ruleset-eleven clients agree on that metadata; ruleset-ten battle journals also remain readable.

Account XP is now banked on wave resolution, battle saving and solo continuation. Per-run receipts prevent repeating a saved segment from awarding the same XP twice, including after account backup/cloud merges. Co-op's account XP display once again belongs to the player; the host's shared arsenal level appears in the build menu. Sandbox awards no XP.

The menu exposes Download saved battle. Account backups now contain both account progress and the untouched local battle journal, with no account credentials. Legacy progress-only backups still import. Importing an older bundle retains a newer local battle.

Validation includes a synthetic tier-five Solar Seraph hunt journal generated by the actual ruleset-nine engine at commit 98cc937, using an anonymous fixture account. It reaches wave ten at tick 13,711. The repaired engine reproduces its original hash, continues fighting, saves it under the new version and restores it again. Tests also cover independent host/guest account levels, banked XP across repeated reloads, full backup round-trips and cloud XP receipt retention. The fixture contains no user backup data.

Functional browser checks exercise the historical Continue button, full battle download, XP saving and repeated Continue, plus the existing mobile, sandbox, co-op and endgame flows. The two-seat recovery script exercises old save → shared room → solo → reload with different account XP on each seat.

The two-seat recovery script also passed against production after deployment. A CI-only failure exposed a separate desktop inspector issue: hovering Raise Ground inserted a tooltip into the bottom-anchored panel, moving its own hover target and repeatedly shifting the controls. Desktop now uses the button's existing native tooltip while retaining the terrain preview; touch hold-to-inspect remains available. A browser regression checks that the Mythic disclosure stays in place during that hover, alongside recovery and mobile hold checks.

A restored solo battle now contributes the player's current earned Mythics after validating its historical replay. That contribution is recorded using the existing shareMastery command, so subsequent saves and co-op transfers retain it. Co-op adoption waits for the room's ordered contribution instead of injecting a client's private unlocks into shared history. Continuing solo also records any earned contribution that had not yet returned from the room. Tests cover an old battle with no mastery stamps, a currently mastered account, repeated saves, disconnecting before a contribution arrives, the inspector's earned stamps, and tier-six purchasing with sufficient gold.
